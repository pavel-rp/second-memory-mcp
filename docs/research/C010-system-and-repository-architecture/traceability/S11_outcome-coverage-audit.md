**This file is the audit set `README.md` reserves for this sub-task**, under the name it reserves
(*"SUB-11 writes `S11_outcome-coverage-audit.md`"*). It is a **separate file, not an edit to anyone
else's**. It carries two kinds of row, kept apart and labelled:

- **§A — audit rows**: the cross-cutting check `README.md` assigns to `NEU-985 (SUB-11)` — that every
  outcome has coverage, that every row's evidence resolves, and that the counts hold. These rows are
  *about other sub-tasks' coverage* and assert nothing about their content's correctness.
- **§B — this sub-task's own coverage**: the two outcome clauses `../16_mechanical-audits.md` itself
  discharges.

Every row below resolves into `docs/research/` or a real repository path. **Zero rows resolve into
`_local/` or `docs/wf-plans/`** — and that is also the property §A's fourth row measures, over all
259 rows of this folder.

Evidence classes are those of `../00_method-and-provenance.md` §1.1; statuses are the three labels of
§1.2 (`confirmed` / `[unconfirmed]` / `consumed`). **A green type-check or lint line is not evidence
about this package's content** and appears in no row below.

**One counting convention, stated before any number is used.** The audits report **surfaces before
results**: how many files, rows or occurrences were examined, then what was found. Three of the four
audits were expected to return zero, and an audit reporting zero is textually indistinguishable from
one that never ran. Every zero below is therefore accompanied by the count of things examined to
reach it.

## What these rows do **not** establish

- **No row asserts any decision is correct.** The audits are mechanical: does a path resolve, does an
  outcome have a row, does an id name a record, is a term used to claim or to deny. Whether a
  boundary is well drawn or an authority well assigned is outside every row above.
- **No row closes another sub-task's open item, lifts a cap, or repairs a defect.** `CAP-S4-1`,
  `CAP-S6-1` and `CAP-S15-1` remain open and unlifted; this sub-task adds no sighting to any.
  `F-S10-6` remains an open routed finding to SUB-6 and is not resolved here.
- **No row is an entry in `../94_package-completeness-gate.md`.** That file is owned solely by
  `SUB-12 (NEU-986)` and is untouched by this sub-task.
- **Every routing in these rows was verified against the tracker child map** restated at
  `../16_mechanical-audits.md` §8.1 — never against the sub-task label written in the file that
  raised the item, because §8.2 establishes that 38 such labels in this package name the wrong id.
