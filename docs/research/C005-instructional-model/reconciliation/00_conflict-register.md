## 1. What this is — and is not

**Is.** The single register that records, for each of the **ten mechanisms** (M01–M10) **plus the fifteen mastery thresholds** (MM-T1…MM-T15), an **alignment / gap / conflict verdict** against the **current coded behavior** of the Second Memory server, read directly from the authoritative source files as a **compatibility fact**. For every confirmed **conflict or gap** it states the **required target behavior** and — for every **learning-critical** divergence — the **enforceable control** that behavior needs (by reference to the owning `DR-Mxx`, which fixed the control's shape).

**Is not.** It **modifies no source file** and **implements nothing** — every implied code change routes to a later implementation charter (`INC-I3` closure is the *verdict*, not the fix). It **authors no mechanism decision** (the ten `DR-Mxx` own those) and **calibrates no threshold** (the mastery model owns MM-T values). It **resolves no conflict**: C1 and C4 stay `unresolved`·non-downgradable; recording a confirmed live divergence *raises* confidence that a conflict is real, never lowers a severity. The coded model is treated as a **compatibility fact, never as accepted pedagogy** — where the literature-derived target and the code disagree, the target governs and the code is recorded as the divergence to be closed, never silently adopted.

## 2. Method — how a verdict is assigned

**Verdict vocabulary (evidence-labeled):**

- **ALIGNMENT** — the live coded behavior matches the DR's required observable behavior/shape. Recorded as a *compatibility* fact (class-2 code-evidence), **never** as a pedagogical endorsement of the code.
- **GAP** — the DR requires a behavior or control the live code **does not implement**, but the code does not actively contradict it (absence, not opposition). Target behavior + (if learning-critical) control stated.
- **CONFLICT** — the live coded behavior **actively contradicts** the DR's required behavior; adopting the code by default would install a behavior the target model rejects. Target behavior + (if learning-critical) control stated, and the contradicted coded behavior is explicitly **not adopted**.

**Evidence discipline.** Every live-behavior claim cites the source file and line. Code facts are **class 2** (`../01_evidence-labeling.md`) — the compatibility/where-the-control-must-live claim only, never endorsement. No DP-transfer validity is claimed (`INC-I1`/F-TR-3 open); no MM-T value is invented (`OC-5`); learning-critical divergences name a **non-prose** control (failure mode + machine-checkable check + enforcement point), all sourced from the already-authored `DR-Mxx` — this register adds no new control, it binds each divergence to its control.

## 4. The three explicitly-flagged re-verifications (verified against live code, not assumed from the audit)

The charter names three audit-flagged behaviors to re-check against the live source rather than adopt from the audit's description. Verdicts:

1. **Prerequisite gating.** The audit described *unlock-on-a-single-success* (`repetitions > 0`). **Live code contradicts the audit's characterization** (L4): the gate is **retrievability-threshold-based** (`estimatedRetrievability ≥ 0.5`), not a success count. **But** the live behavior still falls short of DR-M10's durability gate (L5): the 0.5 reteach threshold is far below the target durability bar (MM-T8 posterior ≈ 0.90, band 0.85–0.95), it is a **reteach trigger, not a fail-closed unlock lock** (the dependent proceeds after reteach regardless of recovery), it reads a **single-point** retrievability rather than a **persisted multi-observation** posterior, and it emits **no observable gate-decision**. **Verdict against DR-M10: GAP (learning-critical, C1).** The `repetitions>0` conflict as literally stated by the audit is **not** the live behavior; the *substance* of C1 — a too-weak prerequisite gate that advances dependents on an under-durable signal — **is confirmed live** and is not adopted. (See M10 row.)

2. **Lapse handling.** Confirmed **exactly as the audit flagged** (L1/L2): a graded failure **fully resets** the chunk (`repetitions → 0`, `interval → 1d`) **regardless of prior depth/stability**; there is **no savings floor**. **Verdict against DR-M09 behavior 2: CONFLICT (learning-critical, C3).** The savings-preserving invariant (`floor(prior_stability) ≤ post_lapse ≤ prior_interval`) is contradicted by the coded full reset and is **not adopted**. (See M09 row.)

3. **LLM grading / over-validation.** Confirmed **as flagged** (L6/L7): the final quality signal is **agent-supplied**, guarded only by a session-scoped **downward** cap that (per F-M08-3/5) catches post-stumble drift but **not uniform first-turn leniency** — the dominant over-validation mode. No deterministic rubric mapper, adversarial fail-closed fixture, or rebuttal-invariance exists; assessment mode additionally **binary-collapses** the signal. **Verdict against DR-M08: CONFLICT (learning-critical, C4).** The delegated-grader-over-validates behavior is confirmed live and is **not adopted**. (See M08 row.)
