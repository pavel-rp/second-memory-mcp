A single record file written by three slices would be exactly that, and the `[P]` claim would be false. The disjointness that makes `[P]` safe therefore has to hold for **both** artifacts a slice writes, and it does: SUB-11, SUB-12 and SUB-13 each write **one node file no sibling writes** (`cl-1-foundational.yaml`, `cl-2-combinatorial.yaml`, `frontier.yaml`) **and one record file no sibling writes** (`05_…`, `06_…`, `07_…`). ## Shape shared by every finding-closing sub-task (SUB-1 … SUB-4, SUB-11 … SUB-13)

Every finding in C008 sits on an **already-merged** PR. Closing one therefore spans two surfaces, and they are not the same PR:

- **Source PR** (610, 612, 625, 631, or — for OUT-3 — the review-only PR that finally obtained the review) — it is where the Copilot thread lives and where the reply must be posted. It is *not* the deliverable.
- **Fix PR** — a new branch off `develop` carrying whatever file change the adjudication upholds. Standard `/wf:tc` → `/wf:tf` path.

A finding is closed only when both have happened: the verdict is recorded as a reply on the source PR's thread, and any upheld fix is merged via the new PR. A sub-task whose findings are all rejected, or all already fixed, produces replies and no code PR — that is a valid completion, not a miss.

The reply endpoint requires the source PR number:
`gh api --method POST "repos/OWNER/REPO/pulls/{SOURCE_PR}/comments/{COMMENT_ID}/replies" -f body="…"`

**624 and 630 are out of every slice's scope.** Their 7 threads stay unreplied by the charter's deliberate, user-authorized decision. No slice replies to them, and SUB-9 must not flag them.
